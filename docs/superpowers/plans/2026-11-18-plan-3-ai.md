# Banners Plan 3: AI Opponents and Number Tuning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Draft.** Written while plan 2 was still being built. Every plan 2 interface it relies on is listed in the last section and must be re-checked against the merged code before this plan is executed.

**Goal:** One person can play a whole match alone against an AI at easy, normal, hard or adaptive, offline, with each faction played to its character, and the game numbers are tuned from bulk AI-against-AI matches.

**Architecture:** A new `src/ai` module plans a turn from a fog-limited input only: the player's `playerView`, the player's own record, and public facts. It rebuilds a believed `MatchState` from that input and runs the real engine on it, so it plays by the same rules as a person. A pure turn driver applies the planned actions to the real match one at a time and asks for a new plan whenever the real view differs from the one the plan expected (an action refused by something unseen, a treasure, a newly seen enemy). On the phone the planner runs in a Web Worker with a time budget; in Node the same code runs in-process for tests and for the bulk simulation script that drives the tuning pass.

**Tech Stack:** Plan 1 and plan 2's stack (TypeScript ~6.0, Vitest ^4.1, oxlint ^1.75, tsx, React ^19.2, Zustand ^5, Vite ^8.2, vite-plugin-pwa ^2.0, Playwright ^1.62, Node 24). No new dependencies. Web Workers are a browser built-in; Vite bundles `new Worker(new URL(...), { type: 'module' })` on its own.

**Spec:** `docs/superpowers/specs/2026-11-18-banners-design.md` (sections 3, 4, 5.7, 7, 8.3, 8.7, 9) and `docs/rules/stage1-rules.md`. `docs/superpowers/plans/2026-11-18-plan-1-followups.md` lists what plan 1 handed to this plan. `docs/superpowers/plans/2026-11-18-plan-2-game-on-screen.md` defines the app this plan extends. Executors read all four. "Rules 13" means section 13 of the rules file.

**Where this sits:** Stage 1 of the design is four plans. This is the third.

1. Rules engine (done, on `main`).
2. The game on screen (being built on `plan-2-game-on-screen`).
3. AI opponents and number tuning (this plan).
4. Live online play over Firebase (drafted separately). In live play the host's phone runs the AI through the same `runAiTurn` stepper this plan builds.

**Not in this plan:** AI in live or remote play (plan 4 wires the stepper to the host), more than two players, hero traits, any rules change other than the two named in Task 12 and the numbers the tuning pass moves.

## Decisions this plan makes

Each is **[Planner's call]** unless marked, with what it costs if wrong. Each is cheap to reverse.

- **The AI reasons from a believed state.** `aiInputFor(state, player)` is the only AI code that reads a real `MatchState`. It copies out the player's view, own record and public facts. `believedState(input)` rebuilds a `MatchState` from that: seen units, explored tiles, own gold and techs, a rival record with zero gold and only its faction's starting tech, `seed` 0 and a fixed `rng`. If wrong: the AI plays slightly worse than a person who remembers past sightings; adding a memory of last-seen enemies later is a contained change.
- **Unexplored tiles are guessed from the map's symmetry.** Rules 1 says the map is point-symmetric, so a person can infer an unexplored tile's terrain from its explored mirror. The believed state uses the mirror's terrain (nothing else: no village, treasure, road or building), and plain field where the mirror is unexplored too. The enemy capital's position is public (rules 1). If wrong: drop the mirror and use field everywhere; the AI explores a little less well.
- **Moves blocked by unseen enemies: the AI finds out by trying, and so does the person.** The believed state has no unseen units, so its legal moves include tiles an unseen enemy blocks. The real engine refuses such a move; the driver records the refusal, the AI is told only that the action was refused, and it replans without it. This plan also switches the person's move highlights to the same believed state (Task 10), so neither side sees a tell-tale gap; a refused tap shows "Something unseen blocks the way." This revisits plan 2's accepted gap. If wrong: one line in the store goes back to `legalActions(state)`.
- **The AI never resigns** and never takes back a planned action. If wrong: a hopeless AI makes the person finish the match by hand.
- **No turn limit or draw in real matches.** Stalled matches are ended only in simulation: at `maxRounds` (default 60) the match stops and is adjudged to the higher standing, flagged `stalled`. Spec 5.6 has only elimination and resignation. If wrong: a real stalemate against the AI drags on; the person can resign.
- **The skill dial is a number from 0 to 1.** Easy is 0.2, normal 0.5, hard 0.85; adaptive starts at 0.5 for a new player and stays within 0.1 to 0.95. If wrong: the three labels feel too close or too far apart; Task 12 measures the ladder and moves the three numbers.
- **Lower skill means more noise, less lookahead, less care about danger, less focus fire, slower economy.** All five come from one table interpolated on the dial (Task 3). Noise only ever chooses among the best few actions, and two hard rules hold at every level: no attack whose counter kills the attacker while the target lives, and an available enemy-city capture is always taken. That is how "never visibly throws" is kept. If wrong: easy may still feel too sharp; widen the table's dial-0 end.
- **The budget is counted in work, not milliseconds.** A plan stops after `evals` engine calls (Task 3), which keeps "same input and seed gives the same turn" true on every machine. A wall-clock deadline is a safety net only (2,500 ms for the first plan of a turn, 1,000 ms for a replan); when it fires the plan ends the turn early. If wrong: on a slow phone hard plays like normal at times, which nobody can see.
- **The AI's random stream is seeded from a per-match `salt`, never from the match seed.** The match seed generates the whole map, so the AI must not see it. `salt` is drawn when the match is created and stored with the AI seat in the match record. If wrong: nothing visible.
- **Adaptive reads the true standing of both sides.** The adaptive controller lives outside the planner, in the driver's caller, and turns true cities, army, tech and income into one number (`standingOf`); the planner itself still sees only its fog. Spec 7 says it "compares its own standing with the human's". If wrong: the dial reacts to an army the AI cannot see; switch `standingOf` to the AI's own view.
- **Adaptive memory is keyed by the person's name on this phone**, stored under `banners.ai.adaptive.v1`, and updated when an adaptive match ends: +0.05 if the person won, -0.05 if the AI won. A deleted or abandoned match changes nothing. Profiles arrive in stage 6. If wrong: two family members sharing a name share a level.
- **Solo play has no curtain.** With one person on the phone, the match screen stays on that person's view the whole time, and the AI's turn plays out on the board: each action with a visible effect waits 450 ms so the person can follow it; actions in fog are applied without a pause. Resign is disabled during the AI's turn (the engine's resign acts for the current player); Home stays available and stops the AI turn, which resumes from the saved actions when the match is continued. If wrong: the pause feels slow or fast; one constant.
- **The AI only takes the second seat**, as the task asks. The person moves first; the person picks the faction with plan 2's switch and the AI takes the other. If wrong: Setup gains a seat swap later.
- **The Mongol forest quirk is fixed as a rules change** (Task 12). Today a Mongol rider with even 1 half-point left may enter a forest, which other riders cannot with 2; the design says forests slow Mongols more. After the fix a moved Mongol rider needs the normal forest cost left, then stops. If wrong: Mongol riders lose a little reach in forest country.
- **The lure quirk stays as written** unless simulation shows it decides matches (Task 12 has the threshold). The AI never asks for a lure that would pull an enemy onto a village or a city it could then capture.
- **Visibility is computed once per query in the engine.** `attackTargets`, `abilityTargets` and `playerView` today recompute `visibleTiles` for every enemy unit they test. Task 1 passes one set through. Results are identical (pinned digests below); `legalActions` on a 24-unit position falls from about 9.4 ms to 2.7 ms in Node. This answers the follow-up "applyAction clones the whole state" too: the AI scores moves without `applyAction` and probes with it only for the few non-move actions, so the clone is not the bottleneck.

## Global Constraints

- Never write an em dash or an en dash anywhere: code, comments, tests, commit messages, docs, text the game shows. Use a hyphen, a colon, or a new sentence.
- Nothing is copied from Hexonia or any other game: no names, text, numbers, art or layouts.
- Code outside `src/engine` imports the engine only through `src/engine/index.ts`. `src/ai` imports only the engine index and other `src/ai` files; it never imports `src/app` or `src/ui`.
- The engine stays pure (plan 1 rules). `src/ai` is pure too except `src/ai/worker.ts`: no DOM, no `Date`, no `Math.random`, no `performance`. Time reaches the planner only through the injected `now` option.
- Nothing outside the engine changes a `MatchState`. The AI's actions reach the real match only through `applyAction`, exactly like a person's.
- The planner never receives a real `MatchState`. Its only input is an `AiInput` made by `aiInputFor`.
- An AI turn never blocks the main thread for more than 100 ms at a time on the phone, and finishes in at most 3 seconds on a mid-range phone (spec 7: "a few seconds at most").
- Game numbers are read from `src/engine/data/*`. Any change to a rules number or rule bumps `RULES_VERSION` and updates `docs/rules/stage1-rules.md` in the same commit.
- No request leaves the phone at run time except for the app's own files. The worker is one of those files and is cached for offline use.
- Every display string lives in `src/ui/text.ts`.
- Tests sit beside the code as `*.test.ts` or `*.test.tsx`. Write the failing test first. Tests that play many whole matches run only when `SLOW=1`; browser tests only when `BROWSER=1`.
- `npm test`, `npm run typecheck` and `npm run lint` are clean at every commit. Every engine and app test from plans 1 and 2 keeps passing.
- Every commit message ends with a `Co-Authored-By:` trailer naming the model that wrote the commit, with the address `noreply@anthropic.com`.
- Work on branch `plan-3-ai`, cut from `main` after plan 2 is merged. Git identity is already set locally. Do not push.

## Review Focus

1. The phone is locked, the app is closed, or the person taps Home in the middle of the AI's turn: on Continue the AI carries on from the actions already saved, never repeats one, never stalls on "thinking", and never acts while the person's turn is showing. Pinned in Task 10.
2. The worker cannot start, throws, or never answers (an old browser, low memory, a bug): the AI turn still completes on the main thread at the easy budget, and the match never hangs. Pinned in Task 9.
3. The AI has nothing useful to do (no units, no gold, every move blocked by unseen enemies): it ends its turn promptly and never loops on refusals. Pinned in Task 7.
4. Taps during the AI's turn: no action is taken for the person, End turn and Resign are disabled, and a late answer from the worker after Home or after a new match is ignored. Pinned in Task 10.
5. Stored data from before this plan: a plan 2 save (all seats human), a save from rules version 1 after Task 12's bump, and a missing or damaged adaptive memory entry. The first resumes, the second is listed as from an older version, the third falls back to 0.5. Pinned in Tasks 8, 10 and 12.

// types.ts
export type AiLevel = 'easy' | 'normal' | 'hard' | 'adaptive';
export interface Rival { id: PlayerId; faction: FactionId; alive: boolean; turnsTaken: number }
export interface AiInput {
  me: PlayerId;
  self: Player;              // own record: gold, techs, explored, alive, turnsTaken
  rivals: Rival[];           // every other player, public facts only
  stamp: number;             // public: the turn counter both players see
  radius: number;
  view: PlayerView;
}
// input.ts
export function aiInputFor(state: MatchState, player: PlayerId): AiInput;   // the only AI function that reads a real state
export function believedState(input: AiInput): MatchState;
export function viewKey(input: AiInput): string;   // what the AI can see, in a form two states can be compared by
// scenarios.ts: positions used by AI tests (built with the engine testkit, explored set filled in)
export function hiddenScout(): { state: MatchState; rider: number; scout: number };   // Mongol to move
export function spartanLine(): MatchState;    // Spartans to move
export function riderRaid(): MatchState;      // Mongols to move
export function openVillage(): MatchState;    // Mongols to move
export function lureFromCity(): MatchState;   // Mongols to move
export function hopelessCharge(): MatchState; // Mongols to move
```

`believedState` rules:

- `tiles`: every key within `radius` of `0,0`. An explored tile is copied from `view.tiles`. An unexplored tile is `{ terrain, resource: null, building: null, road: false, village: false, treasure: false, cityId: null }` where `terrain` is the mirror tile's terrain if the mirror is explored, else `'field'`.
- `units` and `cities`: copied from the view, in the view's order.
- `players`: `self` at index `me`; each rival as `{ id, faction, gold: 0, techs: [FACTIONS[faction].startTech], explored: [], alive, turnsTaken }`.
- `current: me`, `stamp`, `radius`, `rulesVersion: RULES_VERSION`, `seed: 0`, `rng: 1`, `winner: null`, `nextUnitId` and `nextCityId` one above the highest id in the view.

`viewKey` is `JSON.stringify` of: `self.gold`, `self.techs`, `self.explored`, the view's tiles sorted by key, cities sorted by position, and units sorted by position with their `id` left out (a unit the AI just trained gets a different id in the believed state than in the real match, and must not count as a surprise).

export const LEVEL_DIAL: Record<Exclude<AiLevel, 'adaptive'>, number> = { easy: 0.2, normal: 0.5, hard: 0.85 };
export interface Skill {
  topK: number;          // choose among this many best actions
  temperature: number;   // softmax temperature over their scores, in value points
  margin: number;        // never choose an action more than this many points below the best
  lookahead: number;     // follow-up actions examined for each of the best candidates
  danger: number;        // weight on expected losses next turn
  focus: number;         // weight on hitting a target already hurt this turn
  economy: number;       // weight on income, growth and tech
  evals: number;         // work budget per plan (engine probes; a reachable() call counts 1, an applyAction 1)
}
export function skillFor(dial: number): Skill;    // dial clamped to [0, 1]; linear between the two rows below, topK and lookahead and evals rounded
export interface Persona {
  formation: number; hold: number; spread: number; raid: number; forestPenalty: number;
  techOrder: TechId[]; trainOrder: UnitTypeId[]; rewardPick: Partial<Record<number, 0 | 1>>;
}
export const PERSONAS: Record<FactionId, Persona>;
```

Decisions the implementer cannot make alone:

- **Danger.** For each seen enemy unit, every tile within `UNITS[type].move + bonus + range` of it (bonus from `maxMp`, ignoring terrain) gets the damage its attack would do with `damageFor(attackOf, defence 3, cover of that tile)`. Damage from several enemies adds up. Only seen enemies count.
- **Objectives.** Villages on explored tiles not yet a city; enemy cities in the view; the enemy capital's tile from `CONFIG.capitals` (public) while unexplored or still the enemy's; treasures on explored tiles; own cities with a seen enemy within 3 (`defend`); for exploring, the mirror of each explored village, plus the unexplored tile nearest each own city. Values: village 10 (times `1 + persona.spread / 6`), enemy city `12 + 4 * level`, enemy capital 14, treasure 6, defend 15, explore 3.
- **valueOf**, from the AI's point of view: own cities `12 + 4 * level` each, plus `persona.spread`; minus the same for seen enemy cities; own units `unitWorth * hp / maxHp`, minus the same for seen enemy units; `skill.economy * (3 * playerIncome + 0.25 * gold + 3 * techs.length + growth of own cities)`; a unit standing on a capturable village or enemy city +6; minus `skill.danger * unitWorth * min(1, danger[pos] / hp)` per own unit; plus the persona terms of Task 3; plus `0.1 * explored.length`; minus `0.3 * distance` from each own unit with nothing in reach to its nearest objective.
- **moveScore** computes the same terms for just the moving unit before and after, plus the new tiles its sight would explore (one point each, counted with `range`), so moves are scored without cloning the state.

### Task 5: Planning a turn

**Files:**
- Create: `src/ai/plan.ts`, `src/ai/plan.test.ts`

**Interfaces:**
- Consumes: Tasks 2 to 4; `legalActions`, `applyAction`, `reachable`, `attackTargets`, `abilityTargets`, `canCapture`, `rngInt` from the engine.
- Produces:

```ts
export interface PlanOpts {
  dial: number; seed: number;
  refused: readonly Action[];      // actions the real match refused earlier this turn; never planned again
  now?: () => number; deadlineMs?: number;   // safety net only; both absent in tests and simulations
}
export interface Plan {
  actions: Action[];               // always ends with { type: 'endTurn' }; never contains resign
  expect: string[];                // expect[i] = viewKey of the believed state after actions[i]
  evals: number; cutShort: boolean;
}
export function planTurn(input: AiInput, opts: PlanOpts): Plan;
```

The algorithm (the parts the tests do not pin):

1. `b = believedState(input)`; `ctx` from `skillFor(opts.dial)` and `PERSONAS[input.self.faction]`; danger and objectives are computed once and recomputed only after an action that kills, captures or reveals.
2. Phases, in order: choose any pending city reward (`persona.rewardPick`, else option 0); research (the first affordable tech in `persona.techOrder`, if gold left after it still covers the cheapest unit in `trainOrder` or no city has room); units; training (first affordable type in `trainOrder` a city can train, in each city with room, keeping a city tile empty only if a unit standing there has nowhere better); economy (harvest, build, road, walls) while an action's value gain per gold is at least `0.5 / skill.economy`; then `endTurn`.
3. Units are taken in this order: those that can kill a seen enemy this turn, ranged units, melee units, supports, the Camp, the rest; ties by unit id. For one unit the candidates are its attacks, abilities, capture, and moves (`reachable`), plus, for a unit with `retreat`, attack then move. Attacks, abilities and captures are scored by `valueOf` after `applyAction` on `b` (one eval each) plus `ctx.skill.focus * 2` for a target already in `ctx.hurt`; moves by `moveScore`. Staying put scores 0.
4. With `lookahead > 0`, each of the best `topK + 1` candidates is followed by that many greedy best follow-ups for the same unit, and scored by the total.
5. Two filters at every dial, before choosing: drop an attack whose counter would kill the attacker while the target survives (check the `attacked` and `died` events of the probe); drop a lure whose pull would put the target onto a village or a city tile. And one rule: a capture of an enemy city is always chosen when listed.
6. Choosing: among candidates within `margin` of the best, keep the best `topK`; pick one with softmax weights `exp(score / temperature)` from `rngInt` on a stream started at `opts.seed`. A candidate scoring at or below 0 is never chosen over doing nothing with that unit.
7. Each chosen action is applied to `b` with `applyAction`, and `viewKey` of the result is pushed to `expect`. An action the believed engine refuses is a bug: throw in tests (`import.meta.vitest`-free: a plain `Error`).
8. Stop adding actions, and end the turn, when `evals` would exceed `skill.evals` or `opts.now() - start > opts.deadlineMs`; set `cutShort`.

**Files:**

**Interfaces:**
- Consumes: Tasks 2 and 5; `applyAction`, `rngNext`.

```ts
export const MAX_REPLANS = 6;
export interface AiSeat { player: PlayerId; dial: number; salt: number }
export function planSeed(salt: number, stamp: number, replans: number): number;   // (salt ^ Math.imul(stamp + 1, 0x9E3779B1) ^ Math.imul(replans + 1, 0x85EBCA6B)) >>> 0
export interface Cursor { plan: Plan | null; next: number; refused: Action[]; replans: number }
export const START: Cursor;
export type Step = { kind: 'think'; refused: Action[]; seed: number } | { kind: 'act'; action: Action };
export function aiStep(cur: Cursor, real: MatchState, seat: AiSeat): Step;
export function afterThink(cur: Cursor, plan: Plan): Cursor;
export function afterAct(cur: Cursor, action: Action, accepted: boolean): Cursor;

export const ADAPT = { smooth: 0.7, gain: 0.5, maxStep: 0.04, deadband: 0.05, min: 0.1, max: 0.95, start: 0.5, winShift: 0.05 } as const;
export interface AdaptState { dial: number; trend: number }
export function standingOf(state: MatchState, p: PlayerId): number;   // 4 * cities + 2 * sum of city levels + army / 4 + 2 * techs + income
export function gapOf(state: MatchState, ai: PlayerId): number;       // (mine - theirs) / max(1, mine + theirs); two players in stage 1, average of the others from stage 4

It runs once at the start of each AI turn, never during one. `army` is the sum of `unitWorth * hp / maxHp`. Names are trimmed and lower-cased for the key.
